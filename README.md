# ESI v5 Conversational Anamnesis Coverage Benchmark

Code and de-identified data accompanying the paper *"Conversational
Pre-Triage with Large Language Models: Benchmarking ESI v5 Anamnesis
Coverage in Brazilian Portuguese"* (under double-blind review).

This benchmark evaluates how well large language models conduct an
Emergency Severity Index (ESI v5) anamnesis in Brazilian Portuguese.
A variable **triage model** (M_T) interviews a fixed **simulated patient**
seeded from a de-identified clinical case; a fixed **classifier** (M_C)
assigns urgency; and an independent frontier model audits how completely
M_T's questions cover the ESI v5 criteria (the primary metric).

> **Anonymity note.** This repository is shared for peer review through an
> anonymized mirror. Please do not attempt to de-anonymize the authors.

## Repository layout

```
code/
  compare_models.py        cross-model benchmark (M_T x cases), saves transcripts
  evaluate_triage.py       single-conversation pipeline (M_T / patient / M_C)
  opus_coverage.py         independent ESI v5 coverage audit of each conversation
  coverage_analysis.py     per-model coverage stats (bootstrap CI) + Pareto figure
  stats_analysis.py        classification stats (bootstrap/Wilson CI, McNemar)
  run_variance.py          run-to-run variance harness
  reclassify_cot.py        algorithmic ESI v5 relabelling (ground truth)
  select_b1_cases.py       balanced case sampling by algorithmic label
  default.yaml             model registry (IDs only; API keys read from env)
  prompts/                 ESI v5 anamnesis, classifier, and coverage prompts
data/
  coverage_per_conversation.csv       primary metric, per (case, model)
  classification_per_conversation.csv secondary metric, per (case, model)
  coverage_summary.csv                aggregated per-model coverage
transcripts_PENDING_DEID/  (empty — see notice inside)
```

## Data files (de-identified)

Cases are identified only by an opaque `case_id` (`case_001` … `case_100`);
the mapping to source records is **not** distributed. No free-text or
patient-identifiable content is included.

- **`coverage_per_conversation.csv`** — `case_id, model, coverage_score,
  n_questions, n_relevant_criteria, n_investigated, missing_criteria`.
  `missing_criteria` lists ESI v5 criterion *names* (e.g. `estado_mental`),
  never patient text.
- **`classification_per_conversation.csv`** — `case_id, model,
  nurse_esi_level, gt_opus, predicted_sonnet, correct, n_turns`.
- **`coverage_summary.csv`** — per-model mean coverage with 95% CIs,
  mean questions, and coverage/question; backs the main results table.

These files reproduce the paper's coverage table, Pareto figure, and
classification table. Regenerating the *conversations themselves* requires
provider API access and is intentionally not reproducible from shared data.

## Reproducing the analysis

```bash
python -m venv .venv && . .venv/bin/activate        # (or Scripts/activate)
pip install numpy matplotlib
# aggregate coverage stats + figure are computed from data/*.csv
```

Running the full pipeline (`compare_models.py`, `opus_coverage.py`)
additionally requires API credentials (AWS Bedrock / OpenAI / MariTalk),
supplied via environment variables referenced in `code/default.yaml`.

## Data sharing

The de-identified evaluation results above are released openly. The raw
conversation transcripts are **not** included: although generated by
language models, they are seeded from real (de-identified) chief-complaint
text that may contain incidental identifiers. A de-identified release of
the transcripts --- after automated PII scrubbing and clinical review --- is
planned as **future work**.
